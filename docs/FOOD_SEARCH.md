# Поиск продуктов: perek.us и Open Food Facts

Приложение сначала обращается к нашему Backend, который ищет товар в perek.us. При пустом результате, лимите, ошибке или отсутствии настроенного Backend используется Open Food Facts. Отмена операции не запускает следующий запрос. Предыдущие ручные продукты, недавние и избранные находятся локально по штрихкоду.

## Что нужно от владельца сервера

1. Получить бесплатный API-ключ в https://app.perek.us/developers. На бесплатном тарифе проект должен соответствовать условиям некоммерческого использования.
2. На сервере в закрытом `.env` рядом с `compose.yml` добавить `PEREK_API_KEY=...`. Не отправлять ключ в чат, не коммитить и не помещать в xcconfig/Info.plist приложения.
3. Обновить ветку с этой реализацией и выполнить `docker compose up -d --build backend` из каталога проекта. Для первичного развёртывания всех компонентов использовать [SERVER.md](SERVER.md); Backend требует существующей серверной конфигурации независимо от того, что поиск публичный.
4. Передать разработчику публичный корневой HTTPS-адрес Backend, например `https://api.example.com`. Это адрес сервера, а не Bundle ID, адрес сайта или perek.us.
5. В `Config/Local.xcconfig` iOS указать `FITNESS_TRACKER_BACKEND_URL = https:/$()/api.example.com` и пересобрать приложение. Конфигурация аккаунта/резервных копий остаётся отдельной и требует также Authentication URL. Поиск использует только Backend URL.

`FITNESS_TRACKER_BUNDLE_ID = ru.keltor.fitnesstracker` отвечает за идентификатор сборки и не задаёт адрес сервера.

Проверка без ключа в командной строке клиента:

```bash
curl --get --data-urlencode 'q=7622210769459' https://api.example.com/v1/foods/search
```

200 возвращает `{ "products": [...] }`; пустой массив означает отсутствие пригодной карточки. 503 означает отключённого/недоступного поставщика, 429 — ограничение запросов, 502 — некорректный ответ поставщика, 400 — неверный запрос. iOS при этих отказах пробует Open Food Facts. Наличие конкретного Oreo в perek.us до проверки настоящим ключом не заявляется.

## Ограничения и данные

- Бесплатный аккаунт perek.us: 500 запросов/сутки, 150 разных результатов поиска и 50 разных карточек/штрихкодов в сутки. Лимиты общие на аккаунт, а не на каждого пользователя.
- Backend ограничивает свежие запросы поставщику до 18/минуту и 450/сутки UTC, оставляя резерв. Дополнительно публичный маршрут ограничен 12 запросами/минуту на IP. Upstream `429` задаёт общий cooldown через `Retry-After`; автоматических повторов нет.
- Ответы точных пользовательских запросов кешируются в памяти на час, максимум 512 записей. Это не отдельный общий каталог, построенный из дневников пользователей. При перезапуске кеш и локальные счётчики сбрасываются; окончательные лимиты обеспечивает поставщик. Для нескольких реплик нужен общий бюджет; начальная конфигурация рассчитана на один экземпляр Backend.
- Сохраняются только карточки с названием, полными конечными неотрицательными КБЖУ и явной основой 100 г/100 мл. Неполные числа не заменяются нулями. Идентификаторы стабильны; отдельный optional `barcode` совместим с прежним Codable payload. Старые OFF-идентификаторы также поддерживаются при локальном поиске.
- Ключ передаётся только на фиксированный HTTPS-хост perek.us. Переадресации и cookies отключены, журналирование HttpClient отключено, размер ответа ограничен. Запросы и ключи не должны попадать в Nginx access/error logs; пример конфига обновлён.
- Показана ссылка «Данные: perek.us» рядом с данными продукта, в редакторе и сохранённых записях. По условиям поставщика пользователь может сохранять выбранные продукты/порции/КБЖУ в своём дневнике и экспорте; строить из личных записей общий сторонний справочник нельзя.

Официальная документация и действующие условия: https://perek.us/llms-full.txt. Бесплатность функций FitnessTracker не меняется; платный тариф поставщика автоматически не подключается.
