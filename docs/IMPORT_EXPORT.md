# Импорт и экспорт FitLife

Файлы `.fitlife` и `.json` содержат одинаковый JSON-архив UTF-8. Можно перенести всю историю с планами и взвешиваниями или одну тренировку. UUID тренировок, строк, подходов и упражнений сохраняются; вес хранится в килограммах, включая нулевой добавленный вес.

## Использование

1. Откройте **Настройки → Данные → Импорт и экспорт**.
2. Для копии всей истории выберите формат и нажмите **Сохранить файл**. Системный диалог позволяет выбрать место, включая iCloud Drive.
3. Для переноса одной тренировки откройте её карточку и выберите **Экспорт файла** в меню. **Поделиться JSON** остаётся доступным через системное меню sharing.
4. Нажмите **Выбрать файл**, выберите `.json`/`.fitlife`, проверьте сводку и нажмите **Импортировать**. До подтверждения база не изменяется.
5. `.fitlife` можно открыть из «Файлов» через FitLife. JSON зарегистрирован как альтернативный поддерживаемый тип; выберите «Открыть в FitLife». Оба пути показывают тот же preview.

Чтение и импорт можно отменить до записи; ошибку чтения/сохранения можно повторить. Сохранение подтверждённого импорта завершается одной транзакцией. Эти Apple-сценарии реализованы в исходниках и требуют первой проверки в Xcode.

## Формат 4

```json
{
  "format": "com.fitlife.archive",
  "version": 4,
  "exportedAt": 1790000000,
  "workouts": [],
  "templates": [],
  "bodyWeights": []
}
```

Даты — числа секунд с Unix epoch (UTC), с дробной частью. Это сохраняет точность интервалов пауз. Поля workouts/templates соответствуют Codable-моделям Core. Структура exercise включает название, мышечную группу и текст инструкции, поэтому собственные упражнения переносятся вместе с тренировками и планами.

`bodyWeights` содержит отдельные взвешивания (`id`, `measuredAt`, `weightKG`) и необязательный `workoutID` — явную связь с сессией. Отсутствие связи означает независимое взвешивание. Взвешивание сохраняется независимо от существования и статуса тренировки; совпадающий снимок завершённой сессии с тем же `workoutID` не добавляет вторую точку в сводку. Удаление явно связанного взвешивания атомарно очищает совпадающий снимок этой сессии. Независимые записи не объединяются по весу или дате.

Необязательное `Workout.bodyWeightKG` хранит снимок конкретной тренировки. Полный экспорт включает обе записи и их связь; экспорт одной тренировки содержит только её снимок, без отдельных взвешиваний. Текущий вес в настройках восстанавливается из журнала, отдельного поля настроек в архиве нет. [Правила текущего веса и истории](BODY_WEIGHT.md).

В архив не включаются фотографии встроенного каталога, настройки iCloud, разрешения HealthKit/notifications и signing. Файл — обычный JSON, без сжатия или шифрования.

Принимается только архив `com.fitlife.archive` версии 4 с числовыми датами и всеми обязательными коллекциями. Одиночный Workout JSON без оболочки, прежние продуктовые идентификаторы и другие версии отклоняются. Повреждённые данные и повторные UUID внутри файла отклоняются до записи в базу. Ограничения: 30 МиБ, 10 000 тренировок, 1 000 планов и 10 000 отдельных взвешиваний в одном файле.

## Правила импорта

- Перед сохранением показывается сводка новых и пропускаемых записей.
- Новые тренировки, планы и взвешивания добавляются. Архив только с записями веса также можно импортировать. Существующие UUID не перезаписываются, даже если содержимое файла отличается.
- Повторный импорт того же файла не создаёт копии.
- Если активная/приостановленная тренировка уже есть, незавершённые сессии из файла пропускаются. Иначе восстанавливается только самая поздняя из них. Остальные остаются в файле и могут быть импортированы после завершения текущей сессии.
- Перед подтверждением план пересчитывается по актуальным данным repository.
- Весь файл валидируется заранее. SwiftData сохраняет добавления одним save и делает rollback при ошибке. MemoryWorkoutRepository применяет изменения единым обновлением snapshot.
- Импорт не удаляет историю и не запускает экспорт в HealthKit.

Core-кодек, план слияния и Memory repository тестируются на Linux. File providers, системные диалоги, ассоциация расширений, SwiftData-транзакция и UI требуют проверки в Xcode.

Записи пульса и дневная сводка «Здоровья» не входят в JSON/`.fitlife`. Пульс хранится отдельно на устройстве и не синхронизируется через CloudKit; импорт архива не создаёт вымышленные измерения. [Два режима трекера](MI_BAND.md).

Переход на текущие идентификаторы выполняется без обратной совместимости. Поддерживаются только расширения `.fitlife`, `.json` и отдельный CSV-импорт. [Текущие контракты](RENAME.md).

## CSV

CSV из FitSession импортируется тем же workflow с предпросмотром. Разделитель `;`, оба заголовка ПРОПУЩЕН/ПРОПУЩЕННЫЙ, UTF-8/BOM и многострочные заметки поддерживаются. Множитель веса хранится отдельно, нулевые повторения остаются невыполненными. JSON-экспорт использует только текущий архив v4. Неизвестная длительность показывается прочерком и не отправляется в HealthKit. [Полные правила](CSV_IMPORT.md).

## Дропсеты в v4

Optional WorkoutSet.dropStages хранит UUID, вес/повторы и дату каждого дополнительного этапа. completedAt подхода остаётся датой основного этапа. Optional TemplateExercise.plannedSets сохраняет смешанные индивидуальные цели без отметок выполнения. Экспорт и импорт используют только версию 4. Архив с другой версией отклоняется. [Правила и ограничения](DROP_SETS.md).
