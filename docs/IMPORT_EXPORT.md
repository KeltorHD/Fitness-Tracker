# Импорт и экспорт FitnessTracker

Файлы `.fitnesstracker` и `.json` содержат одинаковый JSON-архив UTF-8. Можно перенести всю историю с планами и взвешиваниями или одну тренировку. UUID тренировок, строк, подходов и упражнений сохраняются; вес хранится в килограммах, включая нулевой добавленный вес.

## Использование

1. Откройте **Настройки → Данные → Импорт и экспорт**.
2. Для копии всей истории выберите формат и нажмите **Сохранить файл**. Системный диалог позволяет выбрать место, включая iCloud Drive.
3. Для переноса одной тренировки откройте её карточку и выберите **Экспорт файла** в меню. **Поделиться JSON** остаётся доступным через системное меню sharing.
4. Нажмите **Выбрать файл**, выберите `.json`/`.fitnesstracker`, проверьте сводку и нажмите **Импортировать**. До подтверждения база не изменяется.
5. `.fitnesstracker` можно открыть из «Файлов» через FitnessTracker. JSON зарегистрирован как альтернативный поддерживаемый тип; выберите «Открыть в FitnessTracker». Оба пути показывают тот же preview.

Чтение и импорт можно отменить до записи; ошибку чтения/сохранения можно повторить. Сохранение подтверждённого импорта завершается одной транзакцией. Эти Apple-сценарии реализованы в исходниках и требуют первой проверки в Xcode.

## Формат 3

```json
{
  "format": "com.fitnesstracker.archive",
  "version": 3,
  "exportedAt": 1790000000,
  "workouts": [],
  "templates": [],
  "bodyWeights": []
}
```

Даты — числа секунд с Unix epoch (UTC), с дробной частью. Это сохраняет точность интервалов пауз. Поля workouts/templates соответствуют Codable-моделям Core. `bodyWeights` содержит отдельные взвешивания (`id`, `measuredAt`, `weightKG`). Необязательное `Workout.bodyWeightKG` хранит значение конкретной тренировки; при экспорте одной тренировки чужие взвешивания не добавляются. Структура exercise включает название, мышечную группу и текст инструкции, поэтому собственные упражнения переносятся вместе с тренировками и планами.

В архив не включаются фотографии встроенного каталога, настройки iCloud, разрешения HealthKit/notifications и signing. Файл — обычный JSON, без сжатия или шифрования.

Поддерживается прежний экспорт одной Workout без оболочки, с ISO-8601 датами, если запись проходит валидацию. Новые экспорты всегда используют версионированный формат. Неподдерживаемая версия, повреждённые данные и повторные UUID внутри файла отклоняются до записи в базу. Ограничения: 20 МиБ, 10 000 тренировок, 1 000 планов и 10 000 отдельных взвешиваний в одном файле.

## Правила импорта

- Перед сохранением показывается сводка новых и пропускаемых записей.
- Новые тренировки, планы и взвешивания добавляются. Архив только с записями веса также можно импортировать. Существующие UUID не перезаписываются, даже если содержимое файла отличается.
- Повторный импорт того же файла не создаёт копии.
- Если активная/приостановленная тренировка уже есть, незавершённые сессии из файла пропускаются. Иначе восстанавливается только самая поздняя из них. Остальные остаются в файле и могут быть импортированы после завершения текущей сессии.
- Перед подтверждением план пересчитывается по актуальным данным repository.
- Весь файл валидируется заранее. SwiftData сохраняет добавления одним save и делает rollback при ошибке. MemoryWorkoutRepository применяет изменения единым обновлением snapshot.
- Импорт не удаляет историю и не запускает экспорт в HealthKit.

Core-кодек, план слияния и Memory repository тестируются на Linux. File providers, системные диалоги, ассоциация расширений, SwiftData-транзакция и UI требуют проверки в Xcode.

Записи пульса и дневная сводка «Здоровья» не входят в JSON/`.fitnesstracker`. Пульс хранится отдельно на устройстве и не синхронизируется через CloudKit; импорт архива не создаёт вымышленные измерения. [Два режима трекера](MI_BAND.md).

Переименование: старые `.fitsession` и JSON `com.fitsession.archive` version 1 также читаются. Новый экспорт использует `.fitnesstracker` и `com.fitnesstracker.archive`; UUID, даты и пользовательские названия сохраняются. [Совместимость обновления](RENAME.md).

Архивы версии 1 по-прежнему читаются: отсутствующий `bodyWeights` мигрирует в пустой список, отсутствующий `Workout.bodyWeightKG` — в `nil`. В версии 2 появились взвешивания; актуальный экспорт создаёт версию 3 с множителями и признаком неизвестной длительности. Старому приложению, понимающему только версию 1, для чтения нового архива понадобится обновление. В версии 2 отсутствующий или повреждённый `bodyWeights` отклоняется, а не заменяется пустыми данными. Вес тела хранится в кг отдельно от отягощений. [Фиксация веса](BODY_WEIGHT.md).

## CSV

CSV из FitSession импортируется тем же workflow с предпросмотром. Разделитель `;`, оба заголовка ПРОПУЩЕН/ПРОПУЩЕННЫЙ, UTF-8/BOM и многострочные заметки поддерживаются. Множитель веса хранится отдельно, нулевые повторения остаются невыполненными. Для этих полей новый экспорт использует v3; v1/v2 по-прежнему читаются. Неизвестная длительность показывается прочерком и не отправляется в HealthKit. [Полные правила](CSV_IMPORT.md).
