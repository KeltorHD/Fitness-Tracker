# Импорт CSV из FitSession

Откройте **Настройки → Данные → Импорт и экспорт → Выбрать файл**. Выберите CSV, проверьте сводку и нажмите **Импортировать**. Оба предоставленных варианта экспорта поддерживаются; файлы можно импортировать по очереди. Поддерживается также открытие CSV из «Файлов» через FitnessTracker. Экспорт приложения остаётся JSON/`.fitnesstracker`.

## Поддерживаемые данные

Формат — UTF-8, необязательный BOM, разделитель `;`, кавычки/экранированные кавычки и многострочные заметки. Заголовки: ДАТА, ВРЕМЯ, ТРЕНИРОВКА, УПРАЖНЕНИЕ, ДИСТАНЦИЯ КМ, ВЕС КГ, МНОЖИТЕЛЬ, ВРЕМЯ С, ПОВТОРЕНИЯ, ОТДЫХ С, ПРОПУЩЕН или ПРОПУЩЕННЫЙ, ЗАМЕТКА. Порядок столбцов может отличаться. Пустые строки между тренировками игнорируются.

- Даты `dd.MM.yy`/`dd.MM.yyyy`, время `HH:mm`/`HH:mm:ss`. Используется григорианский календарь и текущий часовой пояс устройства, показанный в предпросмотре. Для двухзначного года 00–69 означает 2000–2069, 70–99 — 1970–1999. Невозможные даты не нормализуются молча.
- Вес снаряда хранится в кг. При пустом весе дополнительное отягощение отсутствует. Это не вес тела; история взвешиваний не меняется.
- Множитель сохраняется отдельно: объём = вес × повторения × множитель. Рекорд веса/1ПМ относится к указанному весу одного снаряда. Множитель виден в подходах и сохраняется при повторе/создании плана.
- Ноль повторений и явно пропущенные подходы остаются невыполненными, без вклада в объём/рекорды. Тренировка без выполненных подходов сохраняется как отменённая; предпросмотр сообщает об этом.
- CSV не содержит меток разминки; они не угадываются по весу. Заметки сохраняются с указанием упражнения/порядкового подхода. Непустые цели отдыха также сохраняются в заметках; интервалы пауз не выдумываются.
- Точные названия/алиасы каталога связываются с его стабильными UUID. Для остальных упражнений сохраняются название и собственный стабильный UUID без предположений о мышечной группе.
- В предоставленных файлах нет времени/дистанции подходов. Если эти поля заполнены в другом экспорте, импорт явно отклоняется с номером строки, а данные не отбрасываются молча.

## Длительность и повторный импорт

В CSV нет окончания тренировки или времени выполнения каждого подхода. Импорт помечает длительность неизвестной; в дневнике и деталях отображается «—». Технические timestamps завершения совпадают с началом и не выдаются за измеренную длительность. Экспорт такой сессии в HealthKit отключён до запроса permissions. Повтор импортированной тренировки запускает обычный новый таймер.

UUID v5 вычисляются из даты, времени и названия сессии; имя файла и часовой пояс не входят в идентификатор. Регистр и лишние пробелы нормализуются; разная пунктуация не объединяет разные тренировки или собственные упражнения. Повторный CSV пропускает существующие UUID без перезаписи правок. Если источник изменился после первого импорта, уже существующая тренировка сохраняется по обычным правилам additive import. CSV не содержит исходных session IDs, поэтому полностью одинаковые дата/время/название считаются одной сессией.

Все строки преобразуются и валидируются до сохранения. Ошибка сообщает номер строки/поле без приватных значений. Действуют пределы 20 МиБ, 100 000 CSV-записей и 10 000 тренировок; длинные группы подходов делятся на строки максимум по 30 с сохранением exercise identity. Сохранение выполняется существующей атомарной транзакцией; до подтверждения данные не меняются. В демо импорт остаётся изолированным.

## Архивы и проверки

Новые экспорты используют архив v3: `WorkoutSet.loadMultiplier`, `TemplateExercise.loadMultiplier` и `Workout.durationIsKnown` переносятся без потерь. Архивы v1/v2 и прежний одиночный Workout читаются: отсутствующий множитель означает 1, отсутствующий признак длительности сохраняет прежнее поведение. Старому приложению для чтения v3 понадобится обновление. [Формат](IMPORT_EXPORT.md).

- **Implemented:** Core CSV parser/importer, стабильные UUID, preview, CSV picker/open-in-place, localized errors, duration/HealthKit guards и сохранение множителей.
- **Linux-tested:** 13 новых Core tests; общий набор — 112. `PortableCSVChecks` проверяет конвертацию, JSON round-trip, отображение неизвестной длительности и повторный импорт. Оба исходных пользовательских файла проверены целиком в Memory repository; личные CSV не включены в коммиты или bundle.
- **Requires Xcode validation:** системный picker/Files/iCloud Drive, SwiftData transaction, UI/ошибки/отмена и написанные Apple unit tests. Apple SDK на Linux не запускался.
- **Requires Apple Developer configuration:** новых capabilities нет; обычный signing приложения.

Внутренний converted archive использует последнюю дату сессии как стабильный exportedAt: исходный CSV не содержит дату экспорта. При обычном новом экспорте из приложения записывается текущая дата экспорта.
