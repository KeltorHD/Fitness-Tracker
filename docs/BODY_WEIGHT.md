# Вес тела

## Результаты

В **Результаты → Весы → Записать** введите реальный вес и дату/время взвешивания. Карточка показывает последнее известное значение, дату и разницу с предыдущей записью. Пока данных нет, показано «—»; при одной записи разница также отсутствует. Положительная/отрицательная разница не оценивается как полезная или вредная.

Кнопка «…» у раздела открывает **Историю веса**. Нажмите запись для исправления. Свайпом можно удалить запись с подтверждением. История включает отдельные взвешивания и значения, явно указанные в завершённых тренировках.

## Вес в тренировке

В активной тренировке и подробностях завершённой тренировки есть строка **Вес тела → Указать вес / Изменить вес**. Поле необязательное, значение по умолчанию отсутствует. После завершения тренировки её вес появляется в общей истории с датой начала сессии. Для правки завершённой тренировки используется существующий проверяемый путь updateCompleted; подходы не меняются.

«Убрать вес из тренировки» очищает только это поле. Удаление такого значения через историю также не удаляет саму тренировку. Повтор тренировки создаёт новое пустое поле веса: прежнее измерение не подставляется автоматически. Вес активной/приостановленной/отменённой сессии в общую историю не включается.

Отдельное взвешивание не переписывает значения прежних тренировок. Если пользователь записал вес отдельно и в тренировке, это два явно созданных источника. Взвешивание из тренировки не копируется в отдельную запись, поэтому его исправление не создаёт дубликат.

## Данные и совместимость

- Хранение только в кг; выбранные фунты преобразуются на границе ввода/отображения. Допустим конечный вес больше нуля и не более 1000 кг.
- Ввод принимает точку/запятую и цифры локали. Частично распознанный текст, единицы в числе, отрицательные значения, NaN и неоднозначные разделители отклоняются.
- Исходная точность существующей записи сохраняется, если при редактировании число не изменялось, например изменена только дата.
- Даты взвешиваний сохраняются абсолютными Date; будущие записи из архива не показываются как уже выполненные измерения.
- `BodyWeightEntry` хранится через SwiftData в существующем `StoredRecord`, kind `bodyWeight`; сохраняются один repository/context и прежняя CloudKit-конфигурация. Модель store не пересоздаётся.
- `Workout.bodyWeightKG` необязателен: старые workout payloads читаются с nil. Архивы JSON/`.fitnesstracker` v2/v3/v4 включают отдельные взвешивания и поля веса тренировок; v1 читается с явной миграцией. Повторный импорт не перезаписывает UUID. [Формат](IMPORT_EXPORT.md).
- При включённой системной CloudKit-синхронизации записи веса синхронизируются вместе с личными данными. Они включаются в полный экспорт. Экспорт одной тренировки включает только её поле веса.
- Вес тела не используется для добавления фиктивного объёма, калорий или отягощения в графики упражнений. Новые HealthKit permissions не запрашиваются; автоматической отправки веса в «Здоровье», виджет или на часы нет.
- Повторная доставка готовой тренировки с Watch не стирает уже записанный на iPhone вес.
- В демо отдельные взвешивания и вес тренировок изолированы в памяти и сбрасываются при выходе. Числа веса из референса не загружаются; демонстрационный набор также не генерирует вес тела.

## Статусы

- **Implemented:** Core-модели, validation/state rules, repository/SwiftData, архив v2/v1 migration, карточка, история, редактор и поля тренировок RU/EN.
- **Linux-tested:** девять новых Core-тестов; общий набор — 112. `PortableWeightChecks` исполняет настоящие Foundation/Observation модели ввода, сводки и истории; проверены структура, локализация, синтаксис и форматирование.
- **Requires Xcode validation:** SwiftData macro/transactions, SwiftUI layouts, ввод/клавиатура, навигация, написанные Apple unit/UI tests и визуальное сравнение. На Linux эти проверки не выполнялись.
- **Requires Apple Developer configuration:** новых capabilities нет; существующие signing/CloudKit для соответствующей конфигурации.
