# Разминка и дропсеты

## Как записать

1. В активной тренировке откройте упражнение и выберите номер незавершённого подхода.
2. Для разминки откройте **⋯ → Разминочный подход** или удерживайте строку. Появится метка «Разминка». Обратно переключает пункт «Рабочий подход».
3. Для дропсета укажите положительный вес рабочего подхода и выберите **⋯ → Сделать дропсетом**. Следующее снижение добавляется через **Добавить снижение веса**. Можно добавить до пяти снижений: всего до шести этапов вместе с основным.
4. Отредактируйте веса и повторы. Начальная цель нового снижения составляет 80% предыдущего веса; это редактируемая цель без отметки выполнения. Каждый следующий вес должен быть строго меньше предыдущего. Последним этапом допустим нулевой добавленный вес.
5. Нажимайте ✓ после каждого выполненного этапа. Выбор автоматически переходит к следующему этапу того же подхода. До последнего этапа отдых не запускается; после последнего используется обычная настройка отдыха.

Разминка и дропсет — разные типы: сначала переключите разминку в рабочий подход, если хотите сделать дропсет. До выполнения основного этапа можно убрать дропсет целиком. После начала структура фиксируется; веса/повторы будущих этапов остаются редактируемыми, выполненные значения и даты защищены. Пауза блокирует выполнение и редактирование.

Карточка использует один номер подхода, общий фон дропсета, номера снижений ↓1/↓2 и подпись «Без отдыха между этапами». В истории невыполненные этапы помечены отдельно. [Превью](previews/workout-set-types.png) и [сравнение обычных и смешанных подходов](previews/set-types-overview.png) содержат только демонстрационные данные.

## Учёт и завершение

- Дропсет считается одним подходом. Дополнительные этапы не увеличивают `totalSets`.
- `completedSets` учитывает подход после выполнения основного этапа; этого достаточно для явного завершения тренировки. `fullyCompletedSets` требует выполнения всех этапов и используется для прогресса активной сессии/Live Activity.
- Объём суммирует только выполненные этапы: вес × повторы × множитель одинаковых снарядов. Разминка исключается из рабочего объёма и рекордов.
- График повторений включает выполненные этапы, график числа подходов считает группу один раз. Максимальный вес и 1ПМ используют основной, самый тяжёлый этап; дополнительные этапы не выдаются за отдельные обычные подходы для оценки 1ПМ.
- Если завершить тренировку посреди дропсета, уже выполненные этапы сохраняются. Будущие этапы не получают фиктивных отметок и не входят в объём/повторы. Отмена тренировки сохраняет прежнюю семантику исключения из статистики.
- Повтор создаёт новые workout/row/set/stage UUID, сбрасывает даты выполнения и переносит только выполненные цели. Невыполненные снижения не добавляются к повтору.

## Данные и совместимость

`WorkoutSet.dropStages` — optional-массив `DropSetStage(id, repetitions, weightKG, completedAt)`. Прежний `WorkoutSet.completedAt` остаётся датой основного этапа. Старые payloads без `dropStages` читаются как обычные подходы; обнуления store и физической миграции SwiftData schema не требуется. Новые данные хранятся в существующем JSON aggregate и передаются тем же Watch/CloudKit путём.

Новый экспорт JSON/.fitnesstracker имеет **версию 4**, читает версии 1–3 и прежний одиночный Workout. Валидация проверяет снижение веса, предел числа этапов, порядок/даты выполнения и уникальность UUID во всей тренировке. Архив с дропсетами, ошибочно объявленный версией 1–3, отклоняется. Старым версиям приложения требуется обновление для импорта v4.

Шаблон, созданный из истории с дропсетами, хранит индивидуальные цели в optional `TemplateExercise.plannedSets`. Это сохраняет соседние разминки, разные веса и множители. Каждый запуск создаёт новые IDs без выполнения. В редакторе такого шаблона показаны индивидуальные цели; их веса/этапы меняются после запуска. Обычные шаблоны сохраняют прежние поля и редактор. CSV не объединяется в дропсеты по одному лишь уменьшению веса: исходный формат не содержит надёжного типа/группы.

Watch logger понимает следующий незавершённый этап; Live Activity/Dynamic Island показывают номер этапа. Optional-поля snapshot сохраняют чтение прежних snapshots. Новые hardware/background capabilities не добавлены.

## Проверки и статусы

- **Implemented:** Core models/rules, редактор/метки RU/EN, статистика, повтор/шаблоны, архив v4, следующий этап Watch/Live Activity и превью.
- **Linux-tested:** 13 новых Core tests и реальные переносимые presentation checks: порядок, даты, отсутствие промежуточного отдыха, объём, zero load, частичное завершение, неизменяемые выполненные этапы, новые IDs, шаблоны и миграции. Все 127 Core tests прошли. SwiftUI/SwiftData/Watch/widgets проверены только parser/lint/resources.
- **Requires Xcode validation:** SDK compilation, UI/keyboard, VoiceOver/Dynamic Type, сохранение/ошибки SwiftData, RU/EN, Live Activity и Watch. Написаны Apple persistence и UI tests; на Linux не запускались.
- **Requires Apple Developer configuration:** обычный signing и уже существующие настройки Watch/widgets/CloudKit. Новых entitlements нет.

Сценарии: [XCODE_VALIDATION.md](XCODE_VALIDATION.md), [формат архива](IMPORT_EXPORT.md).

Цифры этапов редактируются через [цифровую панель](NUMBER_ENTRY.md). Копирование веса вниз не выравнивает веса дропсетов; переход › включает их незавершённые этапы, а копирование числа повторений допускается.
