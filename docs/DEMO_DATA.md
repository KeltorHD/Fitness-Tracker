# Демонстрационный профиль

Откройте **Настройки → Демонстрационные данные → Открыть демо-профиль** и подтвердите действие. Отдельная схема запуска не нужна: кнопка доступна в приложении, включая конфигурацию Personal.

Демо содержит 24 завершённые тренировки за последние восемь недель и три плана: «Всё тело A», «Всё тело B» и «Верх тела». В тренировках есть разминка, рабочие подходы, рост нагрузки, паузы, заметки и отдельные невыполненные подходы. Даты считаются относительно дня загрузки с календарём пользователя; все тренировки находятся в прошлом. Дневник, календарь, графики и рекорды используют обычные алгоритмы приложения.

Все значения вымышлены. Названия планов и тренировок имеют префикс «ДЕМО», заметки объясняют происхождение данных. На экранах профиля и в формах отображается баннер демо-режима. Пульс, калории, сон и замеры тела не генерируются. При английском языке приложения новый набор создаётся на английском; уже созданные записи сохраняют свой язык до перезагрузки демо.

## Перезагрузка и выход

- **Перезагрузить демо-данные** заменяет набор исходными 24 тренировками и тремя планами. Новые записи не добавляются к предыдущему набору.
- **Вернуться к моим данным** возвращает личную историю и планы. Изменения демо-профиля отбрасываются.
- Демо хранится только в памяти. После завершения процесса следующий запуск открывает личную историю; демо-тренировка также не восстанавливается.
- При незавершённой личной тренировке открыть демо нельзя: сначала завершите или отмените её.
- Настройки языка, оформления, единиц и цели общие для обоих профилей. Возврат не откатывает изменённые настройки.

## Хранение и интеграции

Личный repository и SwiftData context остаются прежними. `WorkoutWorkspaceRepository` направляет операции демо в отдельный memory repository. Редактирование, удаление, создание тренировок/планов и импорт файлов в этом режиме затрагивают только его. Проверяется даже совпадение UUID личной и демонстрационной записи. Если чтение личной истории при выходе завершится ошибкой, демо-профиль сохраняется до успешного повтора.

Демо не публикуется в CloudKit, виджет, Live Activities, уведомления, Apple Watch или HealthKit. Датчик Bluetooth отключается; личные записи пульса не читаются и не удаляются из демо. Пришедшая с Watch тренировка не подтверждается как сохранённая в демо — очередь часов остаётся до повторной доставки в личный профиль. Включённая системная CloudKit-синхронизация личного хранилища может продолжать работать независимо; демонстрационных записей в нём нет.

Ручной экспорт JSON/`.fitnesstracker` доступен для проверки переноса данных. Такой файл содержит демонстрационные записи с их названиями и заметками. Явный импорт этого файла позже в личном профиле добавит эти записи по обычным правилам импорта.

## Проверки и статусы

- **Implemented:** Core-генератор, изолированный repository, Settings-кнопки, сброс, возврат, баннеры и ограничения интеграций.
- **Linux-tested:** пять Core-тестов на состав/стабильность данных, RU/EN, DST, изоляцию, активную тренировку и сохранение данных при ошибке. Общий набор — 83 теста; проверены структура, локализация, синтаксис и форматирование Apple-файлов.
- **Requires Xcode validation:** компиляция SwiftUI/AppStore, написанные Apple unit/UI tests, навигация, баннеры, доступность и интеграционные ограничения. На Linux они не запускались.
- **Requires Apple Developer configuration:** дополнительных capabilities для демо нет; действуют обычные требования signing приложения.
